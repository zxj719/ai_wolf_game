一、先认识 ros2 这条命令

Day 0 装好 ROS2 之后，你就有了一条 ros2 命令。它自己什么也不做， 真正干活的是子命令——第一个词决定这次要操作什么东西：

子命令操作对象今天用到的
ros2 pkg包ros2 pkg create 建包、ros2 pkg executables 看包里有哪些可执行
ros2 run单个节点ros2 run 包名 可执行名，启动一个节点，占住这个终端
ros2 node正在运行的节点ros2 node list 看有谁在跑
ros2 topic话题（第六节讲）list / echo / info / hz，本日的排查主力
ros2 launch一组节点Day 2 才用。一条命令按配置文件同时拉起多个节点， 省掉"开五个终端各敲一次 ros2 run"

规律：ros2 <名词> <动词>。忘了某个子命令有哪些用法， 加 --help 就行，比如 ros2 topic --help。 今天只用 run，因为只有两个节点；节点一多就该换 launch 了。

二、动手：建出本周的包

2.1 先把 ~/ros2_lab 升级成工作空间

Day 0 里 ~/ros2_lab 只是个放练习文件的普通目录。要让 ROS2 的编译工具认它， 只差一件事：建一个 src/ 子目录。

mkdir -p ~/ros2_lab/src
cd ~/ros2_lab
ls
env_report.txt  node_shape.py  src

Day 0 的两个练习文件还在，旁边多了 src。这就是 workspace（工作空间）了—— src/ 是唯一你该手动放东西的地方，其余目录待会由编译工具自动生成。

2.2 建包

在 src/ 里面建包：

cd ~/ros2_lab/src
ros2 pkg create my_robot --build-type ament_python --dependencies rclpy std_msgs

包名紧跟在 pkg create 后面写，选项放包名之后。 --dependencies 可以接收多个值，会把后面所有词都当成依赖： 写成 --dependencies rclpy std_msgs my_robot 会报 the following arguments are required: package_name—— 包名被当成第三个依赖吃掉了。包名放最前面就不存在这种歧义。

它会刷出十几行 creating ...，逐行读没有意义。只需确认三行—— 它们对应你命令里给的三个东西：

package name: my_robot
build type: ament_python
dependencies: ['rclpy', 'std_msgs']

末尾还有一条 [WARNING]: Unknown license ...， 可以忽略，它只是提醒你没填开源许可证。本课程不发布代码，不用管。

三个参数分别是什么意思：

参数含义
my_robot包名。本周只建这一个包，后面几天都往它里面加东西
--build-type ament_python这是个纯 Python 包。另一个取值是 ament_cmake（C++ 包），本课程不写 C++
--dependencies rclpy std_msgs这个包要用到哪些别的包。rclpy 是 ROS2 的 Python 接口， std_msgs 提供标准消息类型。它只是替你把依赖写进 package.xml，忘了写以后手动补也行

2.3 它到底生成了什么

现在包已经在手上了，来看看里面每个文件是干什么的。用编辑器打开工作空间：

cd ~/ros2_lab
code .

左边文件树里 src/my_robot/ 的结构是这样（也可以 find src/my_robot | sort 在终端里看）：

注意有两层同名的 my_robot：外层是包目录，里层是放 Python 代码的地方。 刚建好时里层只有一个空的 __init__.py，talker.py 和 listener.py 是待会你自己写的。逐个说清楚：

文件作用不写会怎样
package.xml包的身份证：包名、版本、维护者、依赖哪些别的包、构建类型ROS2 不认这是一个包，colcon build 直接忽略它
setup.pyPython 打包说明：哪个目录是代码、 哪些函数要变成可执行命令、还要安装哪些文件能编译但装不出可执行文件，ros2 run 报 No executable found
setup.cfg告诉 colcon 把可执行文件装到 lib/<包名>/ 下ros2 run 找不到程序
resource/my_robot一个空文件，作用是让 ament 的索引能登记到这个包包不出现在 ros2 pkg list 里
my_robot/__init__.py空文件，标记这个目录是一个 Python 包，可以被 importModuleNotFoundError
my_robot/*.py你的节点代码—
test/ros2 pkg create 自动生成的代码风格检查本课程用不到，可以不管

三个名字必须完全一致：包目录下那个 Python 子目录名、 package.xml 里的 <name>、setup.py 里的 package_name。不一致的后果是编译能过、运行时才报 ModuleNotFoundError， 非常难查。用 ros2 pkg create 建包就不会出这个问题——它三处一起写好了。

2.4 打开 package.xml 核对

在编辑器里点开 src/my_robot/package.xml：

<?xml version="1.0"?>
<?xml-model href="http://download.ros.org/schema/package_format3.xsd" schematypens="http://www.w3.org/2001/XMLSchema"?>
<package format="3">
  <name>my_robot</name>
  <version>0.0.0</version>
  <description>TODO: Package description</description>
  <maintainer email="you@example.com">agx</maintainer>
  <license>TODO: License declaration</license>

  <depend>rclpy</depend>
  <depend>std_msgs</depend>

  <test_depend>ament_copyright</test_depend>
  <test_depend>ament_flake8</test_depend>
  <test_depend>ament_pep257</test_depend>
  <test_depend>python3-pytest</test_depend>

  <export>
    <build_type>ament_python</build_type>
  </export>
</package>

maintainer 那行是你机器上的用户名和邮箱，各人不同。 刚才命令行里写的 --dependencies rclpy std_msgs 变成了这里的两行 <depend>；<build_type>ament_python</build_type> 则是 --build-type 的结果——colcon 靠它决定用 Python 的方式还是 CMake 的方式处理这个包。

阶段成果：~/ros2_lab/src/my_robot/ 已建好， 每个文件的用途你都能说出来。

三、写第一个节点：Publisher

包是个空壳，现在往里放代码。新建 src/my_robot/my_robot/talker.py（注意是里层那个 my_robot，和 __init__.py 放在一起）：

import rclpy
from rclpy.node import Node
from std_msgs.msg import Int32


class Talker(Node):
    def __init__(self):
        # 'talker' 是节点名，ros2 node list 里看到的就是它
        super().__init__('talker')

        # 消息类型、话题名、队列深度
        self.pub = self.create_publisher(Int32, 'counter', 10)

        self.count = 0

        # 每 0.2 秒调用一次 self.on_timer。0.2 秒 = 5 Hz
        self.timer = self.create_timer(0.2, self.on_timer)

        self.get_logger().info('talker 已启动，正在发布 counter')

    def on_timer(self):
        """定时器回调。rclpy 每 0.2 秒调用一次，我们自己从不调用它。"""
        msg = Int32()
        msg.data = self.count
        self.pub.publish(msg)
        self.get_logger().info(f'发布：{msg.data}')
        self.count += 1


def main():
    rclpy.init()
    node = Talker()
    try:
        rclpy.spin(node)
    except KeyboardInterrupt:   # Ctrl+C 时干净退出，不打印一堆红字
        pass
    finally:
        node.destroy_node()
        rclpy.shutdown()

3.1 每个节点都是这个形状

回想 Day 0 的"类 + 回调"。上面这段代码的骨架，之后每个节点都一样：

flowchart TD
    A["rclpy.init()<br/>初始化 ROS2 运行时"] --> B["node = Talker()<br/>触发 __init__"]
    B --> C["__init__ 里做四件事"]
    C --> C1["super().__init__('节点名')<br/>向 ROS2 注册自己"]
    C --> C2["create_publisher(...)<br/>要发消息就建这个"]
    C --> C3["create_subscription(..., 回调)<br/>要收消息就建这个"]
    C --> C4["create_timer(周期, 回调)<br/>要周期性做事就建这个"]
    C1 --> D["rclpy.spin(node)<br/>交出控制权，开始等"]
    C2 --> D
    C3 --> D
    C4 --> D
    D --> E{"有事发生吗"}
    E -- 定时器到点 --> F["调用你的 timer 回调"]
    E -- 消息到达 --> G["调用你的消息回调"]
    F --> E
    G --> E
    E -- "Ctrl+C" --> H["destroy_node()<br/>rclpy.shutdown()"]

看清楚 rclpy.spin() 的位置。 它之后的代码在 Ctrl+C 之前永远不会执行。所有"持续做的事"都必须写成回调， 交给 spin 去调用——不能写成 while True 循环。

3.2 create_publisher 的三个参数

create_publisher(Int32, 'counter', 10)：消息类型、话题名、队列深度。 队列深度的意思是如果订阅者处理不过来，最多缓存 10 条，再多就丢掉最老的。 Day 3 讲 QoS 时会展开，现在填 10 就行。

想知道 Int32 里到底有什么字段：

ros2 interface show std_msgs/msg/Int32
# This was originally provided as an example message.
# It is deprecated as of Foxy
# It is recommended to create your own semantically meaningful message.
# However if you would like to continue using this please use the equivalent in example_msgs.

int32 data

只有一个字段 data，类型是 32 位整数。所以代码里写 msg.data = self.count。

那段"deprecated"的注释不用管。ROS2 官方建议正式项目自定义有语义的消息类型 （比如 BatteryLevel 而不是 Int32），但学习阶段用它最省事。 std_msgs 里的类型在实际项目中仍然到处都是。

四、注册可执行文件，然后编译

4.1 让 ros2 run 知道有这个程序

光有 .py 文件不够，ros2 run 找不到它。打开 src/my_robot/setup.py，把 entry_points 那段改成：

entry_points={
    # 左边是 ros2 run <包名> <这个名字>，右边是 模块路径:函数名
    'console_scripts': [
        'talker = my_robot.talker:main',
        'listener = my_robot.listener:main',
    ],
},

读法：talker 这个命令，对应 my_robot 包里 talker 模块的 main 函数。冒号左边是模块，右边是函数名。

listener 那行现在写上没关系，第六节就会写出这个文件。 但在写出来之前不要去运行它，否则会报找不到模块。

4.2 colcon build 到底做了什么

很多人以为 Python 不用编译，所以 colcon build 是多余的。不是的—— 它做的不是"编译"，而是安装：把你 src/ 里的源码， 按 setup.py 的说明，复制/链接到 install/ 里， 并在那里生成真正的可执行文件。

flowchart TD
    A["src/my_robot/<br/>你写的源码"] --> B["colcon build 读 package.xml<br/>确认包名与构建类型"]
    B --> C["按 setup.py 的说明处理"]
    C --> D["build/<br/>中间产物，可随时删"]
    C --> E["install/my_robot/lib/my_robot/talker<br/>真正的可执行文件"]
    C --> F["install/my_robot/lib/python3.10/<br/>site-packages/my_robot/<br/>你的 .py 被装到这里"]
    C --> G["install/setup.bash<br/>把上面这些位置写进环境变量的脚本"]
    G --> H["source install/setup.bash"]
    H --> I["ros2 run my_robot talker<br/>这时才能找到"]

这就是"改了代码没生效"的原因。 ros2 run 跑的是 install/ 里的那份副本，不是你正在编辑的 src/。改完必须重新 colcon build。

有个省事的办法：colcon build --symlink-install。它把 install/ 里的文件做成指向 src/ 的符号链接而不是复制， 以后改 .py 内容立刻生效，不用重编。但改 setup.py（比如加了新的可执行）仍然必须重新 build。

4.3 编译

先回到 workspace 根目录，确认自己站对了地方再敲编译命令：

cd ~/ros2_lab
ls
env_report.txt  node_shape.py  src

看到 src 就对了。

colcon build 只在 workspace 根目录跑—— 就是那个"里面有 src/"的目录。它会把 build/、 install/、log/ 建在你当前所在的目录下， 并且只编译当前目录下 src/ 里的包。所以在 src/ 里面跑， 或者在家目录里随手跑一下，都会在那儿留下三个目录，而且往往一个包都没编译到 （Summary: 0 packages finished）。敲这条命令前先 pwd 和 ls 确认一眼。已经建歪了就把那三个目录删掉： rm -rf build install log，它们随时可以重建。

colcon build
Starting >>> my_robot
Finished <<< my_robot [1.81s]

Summary: 1 package finished [2.33s]

包多了以后，只编译某一个：colcon build --packages-select my_robot。

看看多出了什么：

ls -1
build
install
log
src

build/、install/、log/ 三个目录由 colcon build 自动生成。不要手动改它们，也不要提交到 git。 删掉它们再重新编译永远是安全的——这也是"编译出了奇怪问题"时的第一招。

再看看 install/ 里到底装了什么——这能让 4.2 那张图变得具体：

find install/my_robot -maxdepth 4 -type d | sort | head -8
install/my_robot
install/my_robot/lib
install/my_robot/lib/my_robot
install/my_robot/lib/python3.10

五、source 并运行

5.1 为什么还要 source 一次

Day 0 你 source 过 /opt/ros/humble/setup.bash，那是让系统认识 ROS2 自带的东西。 现在 source install/setup.bash 是同一个机制，只不过这次是让系统认识你自己写的包。

flowchart LR
    A["新开一个终端<br/>什么都不认识"] --> B["source /opt/ros/humble/setup.bash"]
    B --> C["认识 ROS2 自带的几百个包<br/>ros2 命令可用"]
    C --> D["source ~/ros2_lab/install/setup.bash"]
    D --> E["额外认识你自己的 my_robot<br/>ros2 run my_robot talker 可用"]

Day 0 已经把第一条写进 ~/.bashrc 了，所以新终端自动就有 ROS2。 但第二条通常不写进 bashrc——将来你可能有多个工作空间， 写死一个反而会互相干扰。所以每开一个新终端，都要手动 cd ~/ros2_lab && source install/setup.bash。

六、话题（Topic）与 Subscriber

6.1 节点之间怎么传数据

刚才 talker 在"发布"，但发给谁了？现在补上这个概念。

节点各自跑在自己的进程里，数据得有个办法送过去。先问为什么不用最直接的办法： 假设雷达节点测到了距离，要告诉导航节点，最容易想到的是"雷达节点调用导航节点的函数"。 但这样有几个问题：雷达必须知道导航节点在哪、叫什么；如果又来一个建图节点也想要这个数据， 雷达代码就得改；导航节点崩了，雷达也会跟着出错。

ROS2 的答案是话题（Topic）——一个带名字的数据频道。 发布者（Publisher）只管往频道上扔数据，谁想要谁来订阅（Subscriber）。 双方互相不知道对方存在，只需要约定好话题名和消息类型 （数据格式，比如今天用的 std_msgs/msg/Int32）。 这三个词——话题、Publisher、Subscriber——是今天的核心，后面五天天天出现。

sequenceDiagram
    participant T as talker 节点
    participant D as DDS 网络
    participant L1 as listener 节点
    participant L2 as 另一个订阅者
    Note over T,L2: 双方互不认识，只认话题名和消息类型
    T->>D: publish(Int32 data=5) 到 /counter
    D->>L1: 投递
    D->>L2: 同一份数据也投给它
    L1->>L1: on_msg 回调被调用
    L2->>L2: 它自己的回调被调用
    Note over T: talker 不知道有几个订阅者，也不关心

这带来三个特性，后面每天都会用到：

  • 一对多：一个发布者，任意多个订阅者，发布者代码不用改
  • 解耦：订阅者没启动、或者崩了，发布者照常运行
  • 不补发历史：订阅者只能收到它启动*之后*的消息（默认行为）

"谁想要谁来订阅"也意味着：你没打算给的人，只要话题名对上， 也能收到、也能往里发。同一个局域网里，如果别人的程序恰好用了同名话题 （/scan、/imu、/cmd_vel 这类通用名字尤其容易撞）， 双方的节点会互相看见：多出来的订阅者会分走带宽、多出来的发布者会往同一个话题里掺数据。 真实现象通常不是报错，而是雷达点云突然掉帧甚至断流、话题频率莫名其妙地不稳—— 因为一份数据被多送了几路，或者两个发布者在同一个话题上打架。 两个办法躲开：换 ROS_DOMAIN_ID（Day 0 第四节讲过， 域号不同的节点互相看不见，最省事）；或者给自己的话题加 namespace 前缀， 比如 /robot1/scan——Day 2 就会这么做。Day 3 会展开讲怎么排查这类问题。

6.2 写 Subscriber

新建 src/my_robot/my_robot/listener.py：

import rclpy
from rclpy.node import Node
from std_msgs.msg import Int32


class Listener(Node):
    def __init__(self):
        super().__init__('listener')

        # 类型、话题名、回调函数、队列深度
        # 话题名和类型都必须与发布者一致，否则收不到
        self.sub = self.create_subscription(Int32, 'counter', self.on_msg, 10)

        self.get_logger().info('listener 已启动，正在订阅 counter')

    def on_msg(self, msg):
        """每来一条消息，rclpy 调用一次，并把消息作为参数传进来。"""
        self.get_logger().info(f'收到：{msg.data}')


def main():
    rclpy.init()
    node = Listener()
    try:
        rclpy.spin(node)
    except KeyboardInterrupt:
        pass
    finally:
        node.destroy_node()
        rclpy.shutdown()

注意这里没有定时器。on_msg 什么时候被调用， 完全取决于"有没有消息到达"。这就是 Day 0 讲的回调模型。

self.on_msg 不能写成 self.on_msg()。加了括号是"现在就执行它"， 但此刻并没有消息可传，会直接报错。回想 Day 0 第 5.9 节。

6.4 让 listener 也发布：加工后再传出去

只订阅不发布的节点，在真实系统里很少见。更常见的形态是节点处在数据链路的中间： 订阅一个话题，加工，再发布另一个话题。传感器数据要滤波、坐标要变换、 原始值要换算成物理量——都是这个形状。

给 listener 加一个 publisher，把收到的数乘 2 再发出去。 改动只有三处，用 # ← 新增 标出：

import rclpy
from rclpy.node import Node
from std_msgs.msg import Int32


class Listener(Node):
    def __init__(self):
        super().__init__('listener')

        self.sub = self.create_subscription(Int32, 'counter', self.on_msg, 10)

        # ← 新增：加工后的结果发到另一个话题上
        self.pub = self.create_publisher(Int32, 'counter_doubled', 10)

        self.get_logger().info('listener 已启动，正在订阅 counter')

    def on_msg(self, msg):
        """每来一条消息，rclpy 调用一次，并把消息作为参数传进来。"""
        doubled = msg.data * 2                   # ← 新增：加工

        out = Int32()                            # ← 新增：装进新消息发出去
        out.data = doubled
        self.pub.publish(out)

        self.get_logger().info(f'收到 {msg.data}，发出 {doubled}')

colcon build
source install/setup.bash

[INFO] [1788744446.155627145] [listener]: 收到 15，发出 30

7.1 话题连通的三个条件

"两个节点都在跑，但就是收不到消息"是 Day 1 最常见的问题。原因一定是下面三个之一：

flowchart TD
    A{"话题名完全一致吗"} -- 否 --> A1["ros2 topic list 看实际名字<br/>注意开头的斜杠"]
    A -- 是 --> B{"消息类型一致吗"}
    B -- 否 --> B1["ros2 topic info 看类型<br/>Int32 和 Int64 是两回事"]
    B -- 是 --> C{"QoS 兼容吗"}
    C -- 否 --> C1["Day 3 会讲<br/>Day 1 用默认值不会遇到"]
    C -- 是 --> D["能通"]

今天你只需要盯前两个。排查顺序永远是：先 ros2 topic list 确认名字， 再 ros2 topic info 确认类型和两端数量。

Python 补给站

今天真正用到的语法，都在 Day 0 讲过，这里对照节点代码复习一遍。

1. 继承 Node 与 super().__init__()

class Talker(Node):              # 继承 ROS2 的 Node
    def __init__(self):
        super().__init__('talker')   # 把节点名交给父类去注册

Day 0 第 5.8 节练过：漏了 super().__init__()，父类的初始化没跑， 后面用 self.create_publisher 就会失败。括号里那个字符串是节点名， 不是类名也不是文件名——ros2 node list 显示的就是它。

2. 回调不加括号

self.create_timer(0.2, self.on_timer)                   # 对
self.create_subscription(Int32, 'counter', self.on_msg, 10)   # 对

self.create_timer(0.2, self.on_timer())                 # 错
self.create_subscription(Int32, 'counter', self.on_msg(), 10) # 错

加括号 = 现在执行它、把返回值（None）交出去。 不加括号 = 把函数本身交出去，让 rclpy 在合适的时机调用。

3. self. 保存状态

def __init__(self):
    self.count = 0        # 存进对象，后面的回调还能用到
    self.pub = self.create_publisher(...)   # 也要存起来

def on_timer(self):
    self.count += 1       # 每次调用都在上次基础上累加

如果写成 count = 0（没有 self.）， 它只是 __init__ 里的局部变量，函数一结束就没了， on_timer 里访问会报错。 publisher 也必须存进 self.—— 不存的话它可能被 Python 回收，话题就悄悄断了。

4. f-string 打日志

self.get_logger().info(f'发布：{msg.data}')

self.get_logger() 是 Node 提供的， 比 print() 好：带时间戳和节点名，而且能被 ROS2 的日志系统统一收集。 本课程一律用它，不要用 print()。

5. try / except / finally

try:
    rclpy.spin(node)          # 一直阻塞，直到 Ctrl+C
except KeyboardInterrupt:     # Ctrl+C 触发的就是这个异常
    pass                      # 什么都不做，安静退出
finally:
    node.destroy_node()       # 不管怎么退出，清理都要做
    rclpy.shutdown()

不写 except KeyboardInterrupt 的话，Ctrl+C 会打印一大段红色堆栈， 看着像出了错，其实只是你按了停止。

课后回顾

几道典型选择题，先作答再展开答案；答错的回到括号里的小节重读。 考核题面由带教老师另行下发。

  1. ros2 run my_robot talker 报 Package 'my_robot' not found，最可能的原因是？

    1. entry_points 写错了
    2. 这个终端没有 source install/setup.bash
    3. 节点名写错了
    4. 没有用 --symlink-install
    答案与解析

    B。找不到包是环境没加载；如果报的是 No executable found，才是包找到了但 entry_points 不对或没重新 build（报错表）。这两条报错必须能立刻区分。

  2. 为什么每开一个新终端都要重新 source install/setup.bash？

    1. ROS2 的 bug
    2. 环境变量只活在设置它的那个 shell 里，新终端是新进程，什么都没继承到你的改动
    3. install/ 目录每次都会变
    4. colcon 要求
    答案与解析

    B。Day 0 的 3.3 讲过：source 只影响当前 shell。ROS2 那条已经写进 ~/.bashrc 了，工作空间这条不写，是因为将来可能有多个工作空间（5.1）。

  3. 要 5 Hz 发布，create_timer 的第一个参数填？

    1. 5
    2. 0.5
    3. 0.2
    4. 50
    答案与解析

    C。参数是周期（秒）不是频率：1 / 5 Hz = 0.2 秒。填 5 就成了 5 秒一次（0.2 Hz）。本节的例子填 0.2，跑出来正是 5 Hz（三、七两节）。

  4. 改了 talker.py 再 ros2 run，行为没变化。为什么？

    1. Python 有缓存
    2. ros2 run 跑的是 install/ 里的副本，改的是 src/，中间还差一次 colcon build
    3. 必须重启终端
    4. 必须先杀掉旧节点
    答案与解析

    B。编译的本质是把 src/ 按 setup.py 的说明装进 install/（4.2）。--symlink-install 能省掉改 .py 后的重编，但改 setup.py 仍要重新 build。

  5. 把 self.create_timer(0.2, self.on_timer) 写成 self.create_timer(0.2, self.on_timer()) 会怎样？

    1. 完全一样
    2. 语法错误
    3. on_timer 被立刻执行一次，其返回值 None 被当成回调交出去，定时器永远不会正常触发
    4. 定时器会跑得更快
    答案与解析

    C。加括号 = 现在就调用；不加括号 = 把函数本身交出去，让 rclpy 到点再调（Python 补给站第 2 条，Day 0 的 5.9）。

  6. 在 ~/ros2_lab/src 里面敲了 colcon build，会发生什么？

    1. 和在 ~/ros2_lab 里敲一样
    2. 报错，提示目录不对
    3. 在 src/ 里面又生成一套 build/install/log，且一个包都没编译到
    4. 会把包装到系统目录里
    答案与解析

    C。它在当前目录找 src/，src/ 里面没有 src/，所以输出 Summary: 0 packages finished，同时留下三个空目录（4.3）。删掉它们，回到 ~/ros2_lab 重编即可。

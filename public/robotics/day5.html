动手顺序

一次写完再调试很难定位问题。按这个顺序，每步都有可验证的中间结果：

flowchart TD

    B --> C{"展开成功吗"}
    C -- 否 --> C1["看报错：括号、属性名、宏参数个数"]
    C1 --> B
    C -- 是 --> D["3. check_urdf"]
    D --> E{"单根 base_link 吗"}
    E -- 否 --> E1["有 link 没被 joint 连上"]
    E1 --> B
    E -- 是 --> F["4. 跑 grade_day5.py 的 L1"]
    F --> G{"60 分了吗"}
    G -- 否 --> G1["脚本会列出每一处差异<br/>照着改，不用猜"]
    G1 --> B
    G -- 是 --> H["5. 起仿真，测 L2"]
    H --> I["6. 键盘遥控，验证走的距离对得上"]

第 1 步：只改数值

cd ~/ros2_lab
code src/my_robot/urdf/my_robot.urdf.xacro

改顶部那几行 <xacro:property> 就够了——如果 Day 4 写得规范， 所有尺寸都是通过属性引用的，改属性就全局生效。这正是 Day 4 用 xacro 的回报。

雷达位置注意看清楚：考卷要的是 lidar_joint 的 origin z = 0.10， 相对 base_link 原点，不是"上表面之上 0.10"。

第 2 步：展开看结果

xacro src/my_robot/urdf/my_robot.urdf.xacro > /tmp/exam.urdf
grep -A1 'name="base_link"' /tmp/exam.urdf | head

展开成功不代表数值对，但展开失败一定是语法问题，先解决它。

第 4 步：L1 自测

colcon build --packages-select my_robot
source install/setup.bash
python3 ~/Tutorials4intern/grading/grade_day5.py

L1 不需要起仿真。全对时前七项满分，L2 会明确说未计分：

[通过] xacro 能展开为合法 URDF  (5/5 分)
[通过] 约定的 link 齐全  (10/10 分)
[通过] TF 树单根且全连通  (10/10 分)
[通过] 关节的类型与父子关系正确  (10/10 分)
[通过] 各 link 质量与题面一致  (10/10 分)
[通过] 惯量矩阵与公式计算一致  (10/10 分)
[通过] lidar_joint 的安装位置正确  (5/5 分)
[未通过] L2 仿真可用性  (0/40 分)
    期望：仿真运行中，/scan 与 /odom 有数据
    实际：未检测到任何仿真话题——L2 未计分
----------------------------------
总分：60 / 100

算错时脚本把每处差异都列出来：

[未通过] 惯量矩阵与公式计算一致  (0/10 分)
    实际：base_link.ixx=0.0116(应为0.0416667)；base_link.iyy=0.0241(应为0.0708333)；left_wheel.izz=0.0005(应为0.0009)
    建议：圆柱的 izz 只跟半径有关（m·r²/2），ixx/iyy 还跟长度有关——轮子最容易在这里写错

不要靠猜。 期望值和实际值都印在上面，差在哪一目了然。 反复出现同一处，说明公式用错了而不是算错了。

第 6 步：人工验收

这一项脚本查不了，但最能暴露隐藏问题：

ros2 topic pub -r 10 /cmd_vel geometry_msgs/msg/Twist '{linear: {x: 0.3}}'

另开终端，发之前和 5 秒后各看一次：

ros2 topic echo /odom --once

x 应该增加约 1.5 米（0.3 × 5）。差得多说明 DiffDrive 插件里的 wheel_radius 与你 URDF 的实际轮子半径不一致——这类错误不报任何错。

惯量自查

算完先自己验一遍数量级，比等脚本报错快：

linkixxiyyizz
base_link0.04166670.07083330.1041667
left_wheel / right_wheel0.00048750.00048750.0009
caster_wheel0.0000720.0000720.000072

（写进 xacro 时不必截断到这几位——用宏让它自己算，精度自然是够的。 判定容差是相对误差 1%。）

上表是给你核对量级用的，不是让你直接抄。 口头抽查会问某个数是怎么来的，答不上来这一项不算过。

注意轮子的三个数不全相同：izz（绕自身轴）比 ixx/iyy 大得多。 三个数写成一样是最常见的错误。

常见丢分点

现象原因
惯量项全错抄了 Day 4 的数值，尺寸变了没重算
轮子惯量三个数相同圆柱的 izz 用错公式，izz = m·r²/2
lidar_joint 位置错题目要相对 base_link 原点 0.10，不是上表面之上 0.10
车轮平躺忘了 <origin rpy="1.5708 0 0"/>
车不动驱动轮写成 fixed，或 axis 不是 0 1 0
走的距离对不上DiffDrive 的 wheel_radius 与几何不一致
imu_link 质量项失分没写 <inertial> 段
改完分数没变忘了 colcon build

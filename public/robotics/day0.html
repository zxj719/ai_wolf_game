一、Linux 基础命令

ROS2 的一切都在终端里发生。这一节把后面五天要用的命令一次讲完，分四组： 定位、查看、创建、组合。用到时不再重复解释。

1.1 终端在做什么

终端是那个黑框窗口，只负责显示文字、接收键盘输入。真正干活的是里面运行的 Shell（Ubuntu 默认 bash）：读你的命令、找到对应程序、把它跑起来。

flowchart LR
    A["你敲 ls -l"] --> B["bash 拆开<br/>命令 ls，参数 -l"]
    B --> C["按 PATH 里的目录<br/>逐个找名叫 ls 的程序"]
    C --> D{"找到了吗"}
    D -- 是 --> E["运行它<br/>结果打到终端"]
    D -- 否 --> F["command not found"]

记住右下角这条。后面你会无数次遇到 ros2: command not found。它的含义永远是"bash 按 PATH 找遍了， 没找到叫 ros2 的程序"，不等于"ROS2 没装"。 第三节会讲这两者怎么区分。

补充：为什么 cd 查不到路径

有少数命令不是独立程序，而是 bash 自己的功能，叫内建命令。

which python3
type cd
/usr/bin/python3
cd 是 shell 内建

which 报出外部程序的路径；cd 没有路径，因为它属于 bash 本身。 这也解释了一个常见困惑：写脚本帮你 cd 是没用的——脚本跑在子进程里， 它切的是自己的目录，你的终端不受影响。同样的道理下一节讲 source 时还会用到。

英文界面下这里显示 cd is a shell builtin。本讲义输出抓自中文环境。

1.2 定位：我在哪，去哪里

提示符本身就告诉你在哪。Ubuntu 默认的提示符格式是 用户名@主机名:当前目录$：

agx@ubuntu:~$

读法：用户是 agx，机器叫 ubuntu，当前在 ~（家目录）。 本讲义的输出抓自一台用户名为 agx 的实验机——你的机器上显示的是你自己的 用户名和主机名，后面所有含 agx 或 /home/agx 的输出同理。 切换目录后提示符会跟着变，不需要额外命令去查。 结尾的 $ 表示普通用户；如果是 #，说明你在 root 身份下，要格外小心。

本讲义的命令块只写你要输入的部分，不带提示符。 看到 cd ~/ros2_lab 就是让你敲这一行。

命令作用
cd 目录切换到该目录
cd ..回到上一级
cd（不带参数）回家目录
whoami当前用户名

Linux 的文件挂在一棵树上，树根是 /：

flowchart TD
    R["/ 根"] --> H["/home 用户的家"]
    R --> U["/usr 系统软件<br/>python3 在 /usr/bin"]
    R --> O["/opt 第三方大型软件<br/>ROS2 装在这里"]
    R --> E["/etc 配置文件<br/>apt 软件源在这里"]
    R --> T["/tmp 临时文件，重启即失"]

绝对路径以 / 开头，从树根算起，在哪执行都指同一处； 相对路径从当前目录算起。. 是当前目录，.. 是上一级， ~ 是家目录。

1.3 查看：目录里有什么

命令作用
ls列出文件名
ls -l加上权限、大小、修改时间
ls -a连隐藏文件一起列（名字以 . 开头的）
cat 文件把文件内容打到终端
head -n 5 文件只看前 5 行
tail -n 5 文件只看后 5 行

-a 很重要。~/.bashrc 这类配置文件都是隐藏的， 不加 -a 你会以为它不存在。第三节要改的就是它。

补充：ls -l 开头那串 -rw-rw-r-- 怎么读

共 10 个字符。第 1 个表示类型，后 9 个分三组表示权限。

位置含义
第 1 位- 普通文件，d 目录，l 符号链接
第 2–4 位文件主人的权限
第 5–7 位同组用户的权限
第 8–10 位其他所有人的权限

每组三位固定是 r 读 / w 写 / x 执行， - 表示没有该权限。所以 -rw-rw-r-- = 普通文件， 主人和同组可读写，其他人只读。

x 对目录的含义是"可以进入"，不是"可以执行"。 装 .deb 那节会再遇到 x。

1.4 创建与重定向：把输出存进文件

先认识 echo：把你给它的文字原样打出来。它和 cat 是一对—— echo 打的是你写在命令里的字符串，cat 打的是文件的内容：

echo "hello"
hello

默认情况下命令的输出打在屏幕上。重定向可以把它改存到文件里—— echo 配上重定向，就是往文件里写一行字的最短路径，第三节改 ~/.bashrc 用的正是这一招。

符号作用风险
mkdir -p 路径建目录，-p 表示缺几层建几层—
命令 > 文件覆盖写入：先清空文件，再写原内容全没
命令 >> 文件追加写入：保留原内容，加在末尾安全

改配置文件时永远用 >>。 差一个字符，> 会把你的 ~/.bashrc 清空。第三节马上要用到。

1.5 组合：管道

管道 | 把左边命令的输出，直接交给右边命令当输入。 这让每个小命令可以拼成一条流水线。

最常配管道用的是 grep 关键词：只留下含关键词的行。

例子：/etc/os-release 记录着系统版本信息，有十几行。 只想看版本号那一行：

cat /etc/os-release | grep VERSION_ID
VERSION_ID="22.04"

读法是从左往右：把整个文件打出来 → 只留含 VERSION_ID 的行。 这个形态后面天天用：dpkg -l | grep ros-humble 查装了哪些 ROS2 包、 ros2 topic list | grep imu 在一大串话题里找传感器的那几个。

1.6 动手：搭出工作台

建立 ~/ros2_lab/，并在其中写出本机的环境报告。

mkdir -p ~/ros2_lab
cd ~/ros2_lab

提示符会跟着变，这就是你已经进去的确认：

agx@ubuntu:~$ mkdir -p ~/ros2_lab
agx@ubuntu:~$ cd ~/ros2_lab
agx@ubuntu:~/ros2_lab$

先用 > 建立报告文件。lsb_release 打印 Ubuntu 的发行版信息， -d 表示只要描述行（description）：

lsb_release -d > env_report.txt
cat env_report.txt
Description:	Ubuntu 22.04.5 LTS

再用 >> 追加两行。uname 打印内核与硬件信息， -m 表示只要机器（machine）架构：

python3 --version >> env_report.txt
uname -m >> env_report.txt
cat env_report.txt
Description:	Ubuntu 22.04.5 LTS
Python 3.10.12
aarch64

uname -m 是 CPU 架构。台式机通常是 x86_64， 这份输出抓自一台 Jetson，所以是 aarch64。

下面验证 > 的覆盖行为：

echo "只剩这一行" > env_report.txt
cat env_report.txt
只剩这一行

三行内容全没了。把它重建回来：

lsb_release -d > env_report.txt
python3 --version >> env_report.txt
uname -m >> env_report.txt
cat env_report.txt
Description:	Ubuntu 22.04.5 LTS
Python 3.10.12
aarch64

确认文件已生成：

ls -l
总计 4
-rw-rw-r-- 1 agx agx 55  7月 30 04:30 env_report.txt

1.7 CPU 架构：为什么 uname -m 的结果很重要

上面报告里那行 aarch64 是 CPU 的指令集架构。 它决定了哪些软件包能装在这台机器上——第二节装 ROS2 时会直接用到。

两大阵营，各有两个名字，指的是同一件事：

阵营uname -m 的叫法软件包里的叫法典型设备
Intel / AMDx86_64amd64 台式机、笔记本、绝大多数服务器
ARM 64 位aarch64arm64 手机、树莓派、NVIDIA Jetson、Apple 芯片的 Mac

同一台机器，两条命令给出的名字不同，但说的是一回事：

uname -m
dpkg --print-architecture
aarch64
arm64

软件包不能跨架构安装。 给 amd64 编译的 .deb 装不到 arm64 机器上，反之亦然。 第二节讲 dpkg -I 时，输出里的 Architecture 字段就是用来核对这个的。 Python 源码本身与架构无关，但它依赖的编译好的库（包括 ROS2 的大部分组件）有关。

补充：NVIDIA 的几条产品线，以及和普通 PC 的区别

机器人领域常听到 Jetson、AGX、DGX、Thor 这些名字，容易混。它们的定位差别很大：

平台CPU 架构用在哪特点
普通 PC / 工作站x86_64 开发、训练模型 算力强、功耗高、体积大。你写代码用的就是这个
Jetson 系列
（Nano / Xavier / Orin， AGX 是其中的高端型号）		 aarch64 装在机器人本体上 CPU 与 GPU 集成在一块模块上，功耗几十瓦，可以电池供电。 代价是算力弱于同代桌面 GPU
DGX 系列x86_64 数据中心，大规模训练 整机柜级别，多张高端计算卡，功耗数千瓦。不会装到机器人上
Thoraarch64 新一代车载与机器人平台 定位是 Orin 的后继，面向对算力要求更高的自动驾驶与具身智能场景

对本课程的实际影响：你在 x86_64 台式机上开发， 而机器人上跑的很可能是 aarch64 的 Jetson。 你写的 Python 节点代码两边通用，但 apt 装的包、Docker 镜像必须分架构准备。 本讲义的实测输出抓自一台 Jetson AGX Orin，所以你会看到 aarch64； 在你自己的台式机上应该是 x86_64，这不是错误。

二、软件从哪来：apt 与 dpkg

2.1 为什么需要包管理器

ROS2 由几百个互相依赖的包组成，每个又依赖一堆系统库。手工下载编译的话， 你要自己解决"A 要 B 的 2.1 版，C 要 B 的 2.3 版"这类冲突——这叫依赖地狱， 靠人做不完。

Ubuntu 用两层工具解决它，分工明确：

dpkgapt
层级底层上层，建在 dpkg 之上
管什么单个 .deb 文件的解包、安装、记账 从软件源找包、算依赖、批量下载，再交给 dpkg 装
会自动装依赖吗不会，缺依赖就报错停下会
什么时候用手里已经有一个 .deb 文件绝大多数时候
flowchart LR
    A["软件源<br/>packages.ros.org"] -->|"apt update<br/>取回目录清单"| B["本地包索引"]
    B --> C["apt install<br/>算出全部依赖"]
    C --> D["下载一批 .deb"]
    D --> E["校验 GPG 签名"]
    E --> F["逐个交给 dpkg 解包安装"]
    F --> G["dpkg 记账<br/>哪个文件属于哪个包"]

2.2 四个必须分清的概念

概念是什么为什么需要
软件源 存放软件包的服务器地址，记在 /etc/apt/sources.list.d/ Ubuntu 自带的源里没有 ROS2，装之前必须先把 ROS 的源加进去
apt update 只刷新"目录清单"，不装任何东西 加完新源必须跑一次，否则 apt 不知道新源里有什么， 会报 Unable to locate package
GPG 密钥 验证下载的包确实来自它声称的来源、没被篡改 你在让别人的代码以管理员权限进入系统。没有它 apt 会直接拒绝
sudo 以管理员（root）身份执行这一条命令 装软件要写 /opt、/usr，普通用户没权限

sudo 意味着这条命令可以对系统做任何事，包括毁掉它。 养成习惯：敲 sudo 前先把整行读一遍，尤其是从网上复制来的。 本课程只有装软件需要 sudo。

2.3 装 ROS2 Humble

安装步骤以 Humble 官方安装文档 为准。ROS2 的软件源地址和密钥获取方式偶有变动，若下面的命令与官方文档不一致，按官方文档执行。

先确认系统版本。ROS2 每个发行版只配特定的 Ubuntu：Humble 配 22.04， 20.04 和 24.04 都装不上。

lsb_release -a
Distributor ID:	Ubuntu
Description:	Ubuntu 22.04.5 LTS
Release:	22.04
Codename:	jammy

代号 jammy 下一步加软件源时要用。

① 启用 universe 分区（社区维护区，ROS2 的部分依赖在这里）：

sudo apt install software-properties-common
sudo add-apt-repository universe

② 装 GPG 密钥：

sudo apt update && sudo apt install curl -y
sudo curl -sSL https://raw.githubusercontent.com/ros/rosdistro/master/ros.key \
  -o /usr/share/keyrings/ros-archive-keyring.gpg

③ 添加 ROS2 软件源：

echo "deb [arch=$(dpkg --print-architecture) signed-by=/usr/share/keyrings/ros-archive-keyring.gpg] \
http://packages.ros.org/ros2/ubuntu $(. /etc/os-release && echo $UBUNTU_CODENAME) main" \
  | sudo tee /etc/apt/sources.list.d/ros2.list > /dev/null

拆开看：$(dpkg --print-architecture) 自动填 CPU 架构； signed-by= 指定用刚才那个密钥验证； $(. /etc/os-release && echo $UBUNTU_CODENAME) 自动填 jammy。 末尾用 tee 而不是 >，是因为 > 由 bash 执行，sudo 管不到它， 直接写 /etc 会 Permission denied。

写完打开看一眼，确认内容对：

cat /etc/apt/sources.list.d/ros2.list

④ 刷新索引并安装：

sudo apt update
sudo apt install ros-humble-desktop python3-colcon-common-extensions

ros-humble-desktop 是 ROS2 核心 + rviz2 + 示例。 python3-colcon-common-extensions 是编译工具 colcon， 它不属于 ROS 的包，必须单独装——漏了它 Day 1 会卡在 colcon: command not found。这一步要下载一两个 G。

ROS2 已安装到 /opt/ros/humble。 但现在敲 ros2 仍然会说找不到——第三节解决。

2.4 dpkg：手上有一个 .deb 时

有些软件（厂商驱动、内部工具）不在任何软件源里，只给你一个 .deb 文件。 Day 3 的 Livox 雷达驱动就可能是这种情况。这时要用 dpkg。

装之前先看清楚它是什么。这两条命令都不需要 sudo， 因为它们只读文件、不改系统：

dpkg -I tree_2.0.2-1_arm64.deb
 新格式的 Debian 软件包，格式版本 2.0。
 大小 47220 字节：主控包=754 字节。
 Package: tree
 Version: 2.0.2-1
 Architecture: arm64
 Installed-Size: 105
 Depends: libc6 (>= 2.34)
 Section: utils

三件事要核对：Architecture 必须和你的机器一致 （uname -m 的结果，台式机是 amd64）； Depends 列出它需要什么；Version 是版本。

dpkg -c tree_2.0.2-1_arm64.deb
drwxr-xr-x root/root         0 2022-02-17 07:55 ./
drwxr-xr-x root/root         0 2022-02-17 07:55 ./usr/
drwxr-xr-x root/root         0 2022-02-17 07:55 ./usr/bin/
-rwxr-xr-x root/root     72960 2022-02-17 07:55 ./usr/bin/tree
drwxr-xr-x root/root         0 2022-02-17 07:55 ./usr/share/
drwxr-xr-x root/root         0 2022-02-17 07:55 ./usr/share/doc/

-c 列出它会往系统里放哪些文件。装陌生来源的 .deb 前先看这个， 确认它不会往奇怪的地方写东西。注意 ./usr/bin/tree 的权限是 -rwxr-xr-x——带 x，所以装完就能当命令执行。

安装的完整流程：

# 1. 确认文件在，看清楚名字和大小
ls -l ./tree_2.0.2-1_arm64.deb

# 2. 安装。-i 是 install
sudo dpkg -i ./tree_2.0.2-1_arm64.deb

# 3. 如果上一步报缺依赖，用 apt 补齐后自动完成安装
sudo apt install -f

# 4. 验证：文件装进去了吗，命令能用吗
dpkg -L tree | head
which tree

第 3 步是关键。dpkg 不会自动装依赖， 缺依赖时它会把包留在"已解包但未配置"的半成品状态并报错。 sudo apt install -f（-f = fix-broken）会把缺的依赖补上、 并完成那个半成品包的配置。看到 dpkg 报依赖错误，不要重复 dpkg -i， 直接跑这条。

补充：关于 .deb 的执行权限

.deb 是数据文件，不需要给它加执行权限—— 你不是运行它，而是让 dpkg 读它。 如果有人让你对 .deb 执行 chmod +x，那是把它和 .run / .sh 安装包搞混了。

真正需要 chmod +x 的是脚本。比如本仓库的 serve.sh：

chmod +x serve.sh    # 给文件主人加上执行权限
ls -l serve.sh       # 第 2-4 位会从 rw- 变成 rwx
./serve.sh

三、环境变量与 source

3.1 三个概念，自上而下

PATH 其中最重要的一个：一串目录，bash 就是按它去找你敲的命令
source 把一个脚本就地执行，让它设的变量留在当前终端里

3.3 source 与直接执行的区别

关键在于：每个程序跑在自己的进程里，进程之间的环境变量互不影响。

直接执行一个脚本，bash 会另开一个子进程去跑；脚本里设的变量活在子进程里， 它一退出就全没了，你的终端毫无变化。source 脚本（也可写成 . 脚本） 则不开子进程，就在当前 shell 里执行一遍，于是变量留了下来。

亲手验证一次。先看 source 之前：

再看 source 之后：

推论：source 只对当前终端窗口生效。 新开一个终端、或关掉重开，它又是空的。后面五天里只要新开终端就必须重新 source， 否则 ros2 命令找不到、你自己写的包"不存在"。这不是 bug。

逐行解释：

变量含义什么时候你会碰它

ros2 命令在当前终端可用。 验证一下：which ros2 应该输出 /opt/ros/humble/bin/ros2。

3.5 让它每次都自动生效

每开一个终端都手动 source 并不现实。~/.bashrc 是一个特殊文件： 每次打开新终端，bash 都会自动 source 它一次。 把那行写进去，就等于让它自动执行。

先打开查看文件原有内容，再决定怎么改：

nano ~/.bashrc

nano 是最简单的终端编辑器。底部那排提示里 ^X 的 ^ 就是 Ctrl。

按键作用
方向键 / PageUp PageDown移动、翻页
Ctrl+W搜索
Alt+/跳到文件末尾
Ctrl+O 回车保存
Ctrl+X退出

翻一遍你会看到：里面已经有几十行 Ubuntu 预置的内容——设置提示符颜色、 定义 ll 之类的别名、加载补全。这些都别动。 确认末尾没有 ROS 相关的行之后，Ctrl+X 退出。

现在再追加。你已经知道文件原本有内容，所以必须用 >>：

确认加成功了：

刚改完的 .bashrc 对当前终端不生效， 因为它只在终端启动时被读一次。要么关掉重开，要么手动 source ~/.bashrc。 这又是一次"source 只影响当前 shell"。

验证：新开一个终端，什么都不做，直接敲：

四、网络基础

上一节最后那个 ROS_LOCALHOST_ONLY 引出一个问题：什么算"同一个网络"？ 这一节回答它。你会在三个地方用到：

  • Day 3：Livox 雷达用网线接主机，两边 IP 必须在同一子网，否则一个包都收不到
  • 多台机器一起跑 ROS2 时，节点能不能互相发现，取决于它们在不在同一个局域网
  • IMU 这类设备常走串口而不是网口，接法完全不同

4.1 IP 地址与子网掩码

IP 地址是设备在网络里的门牌号，四段数字，每段 0–255。 子网掩码回答一个问题：这个门牌号里，哪几段代表"小区"，哪几段代表"门牌"？ 同一个小区的设备可以直接对话，跨小区就得经过路由器转发。

子网掩码简写前几段固定同一子网的范围
255.255.255.0/24前 3 段 192.168.160.0 ~ 192.168.160.255，共 256 个
255.255.252.0/22前 2 段 + 第 3 段的高 6 位 172.16.20.0 ~ 172.16.23.255，共 1024 个
255.0.0.0/8第 1 段 127.0.0.0 ~ 127.255.255.255

最常见的是 /24，也最好判断：前三段相同就是同一子网。 比如主机 192.168.160.200 和雷达 192.168.160.10， 前三段都是 192.168.160，能通； 换成雷达 192.168.123.10，前三段不同，直接不通。

/22 这类非整段掩码要格外小心。若一台主机是 172.16.22.51/22，它的同子网范围横跨 172.16.20.x 到 172.16.23.x 四个整段——172.16.21.58 与它是邻居， 尽管第三段不同。判断是否同一子网必须依据掩码，不能只看前三段是否相同。

这份输出抓自一台机载计算机——你的机器上网卡的数量、名字、IP 都会不同， 台式机上通常只有 lo、一个有线（enp…）、一个无线（wlp…）三行。 要学的是认出每一行是什么：

名字是什么本机情况
lo 本地回环，永远是 127.0.0.1。 机器自己跟自己通信用，不经过任何硬件 永远在。localhost 就是它的别名

wl 开头 无线网卡（wlan0、wlP1p1s0 都是） UP，DHCP 分到 172.16.22.51/22

网卡名不是固定的。教程里常见的 eth0、 wlan0 是老式命名；现在 Ubuntu 用"可预测命名"，会变成 eno1、enp3s0、wlP1p1s0 这种。 看前缀就够了：en = 有线，wl = 无线， lo = 回环。

WiFi 的 IP 会变。它由路由器动态分配（DHCP）， 重连、重启或租约到期后可能换一个。昨天还连得上的机器今天连不上， 先到它跟前用 ip -br addr 或 ifconfig 查当前的 IP， 别信记忆里的旧地址。给雷达配的网口静态 IP 没有这个问题（4.5 节）。

4.4 ping 不通怎么查

ping 是最基本的连通性测试。它的三种失败方式含义完全不同， 分清了就能定位问题在哪一层。

情况一：通。

ping -c 2 172.16.20.1
64 bytes from 172.16.20.1: icmp_seq=1 ttl=64 time=7.97 ms
64 bytes from 172.16.20.1: icmp_seq=2 ttl=64 time=1.87 ms

--- 172.16.20.1 ping statistics ---
2 packets transmitted, 2 received, 0% packet loss, time 1001ms

time 是往返延迟。局域网内正常是零点几到几毫秒。

情况二：Destination Host Unreachable。

ping -c 2 172.16.22.250
From 172.16.22.51 icmp_seq=1 Destination Host Unreachable
From 172.16.22.51 icmp_seq=2 Destination Host Unreachable

--- 172.16.22.250 ping statistics ---
2 packets transmitted, 0 received, +2 errors, 100% packet loss

这条信息比静默丢包更有价值。它说明"路由是通的—— 对方和我在同一子网，我在这个网段里喊了，但没人应答"。 通常是对方没开机、IP 设错了、或者网线没插。

情况三：什么都没有，直接 100% 丢包。

ping -c 2 192.168.123.1
PING 192.168.123.1 (192.168.123.1) 56(84) bytes of data.

--- 192.168.123.1 ping statistics ---
2 packets transmitted, 0 received, 100% packet loss, time 1021ms

连一行错误都没有，才是最典型的"子网配错了"。 本机在 172.16.22.x 和 192.168.160.x 上， 192.168.123.1 两个都不属于，包被丢给默认网关然后石沉大海。 Day 3 接雷达时 ping 不通，多数属于这一种。

4.5 把主机改到同一子网

这是 Day 3 接雷达前必做的一步。设备的 IP 通常是厂商写死的 （比如某些雷达固定在 192.168.123.x 网段），改不了， 所以只能把主机挪过去。

先确认设备的 IP 和网段——查它的说明书或标签，别猜。假设是 192.168.123.10，掩码 255.255.255.0， 那主机需要一个 192.168.123.x 的地址（x 别和设备撞车）。

临时方案（重启后失效，适合先验证能不能通）：

# 1. 确认网线插在哪个网卡上，找 state UP 且没有 IP 的那个
ip -br addr

# 2. 给它加一个 IP。注意 /24 就是掩码 255.255.255.0
sudo ip addr add 192.168.123.100/24 dev eno1

# 3. 确保网卡启用
sudo ip link set eno1 up

# 4. 验证
ip -br addr show eno1
ping -c 3 192.168.123.10

用 ip addr add 是增加一个 IP， 不会顶掉原有的。所以主机可以一边用 WiFi 上网，一边用网口连雷达。 想撤销：把 add 换成 del。

永久方案：用桌面右上角的网络设置， 找到对应的有线连接 → IPv4 → 方式选"手动" → 填地址 192.168.123.100、掩码 255.255.255.0、网关留空。 网关一定要留空——这条线只用来连雷达，不走它上网； 填了网关会把默认路由抢过去，导致整机断网。

不要通过 SSH 远程执行网络配置命令。 改错一步就可能切断你正在使用的连接，届时只能到机器跟前接键盘恢复。 在本机操作，或确保出问题时能物理接触到设备。

4.6 ROS2 在网络上如何通信

前面五小节讲的是"两台机器的 IP 能不能互通"。IP 通了只是前提， ROS2 节点能不能互相发现，还要再过三关。

DDS：ROS2 的通信底座

ROS2 没有中心节点。它不像 ROS1 那样需要先起一个 roscore， 而是让每个节点自己在网络上广播"我在这，我发布这些话题"，同时监听别人的广播。 这套机制由 DDS（Data Distribution Service）提供， ROS2 只是在它之上包了一层。

这个设计的直接后果：只要在同一个局域网、同一个域内，节点就会自动互相发现， 不需要任何配置。方便，但也意味着你的节点会被同网段的其他人看到。

flowchart TD
    A["你的 ROS2 节点"] --> B["rclpy / rclcpp"]
    B --> C["RMW 抽象层<br/>统一接口，屏蔽下面的差异"]
    C --> D1["rmw_fastrtps_cpp<br/>Fast DDS"]
    C --> D2["rmw_cyclonedds_cpp<br/>Cyclone DDS"]
    C --> D3["rmw_connextdds<br/>RTI Connext"]
    D1 --> E["UDP 组播 / 单播"]
    D2 --> E
    D3 --> E
    E --> F["网线 或 WiFi"]

RMW（ROS MiddleWare）是中间那层抽象。ROS2 不绑定某一个 DDS 实现， 换一个实现不用改代码，只改一个环境变量。查看当前用的是哪个：

ros2 doctor --report | grep -A2 "RMW MIDDLEWARE"
   RMW MIDDLEWARE
middleware name    : rmw_fastrtps_cpp

Humble 的默认实现是 Fast DDS（rmw_fastrtps_cpp）。 环境变量 RMW_IMPLEMENTATION 为空时用的就是它。

实现环境变量取值说明
Fast DDSrmw_fastrtps_cpp Humble 默认，装 ROS2 时自带
Cyclone DDSrmw_cyclonedds_cpp 需另装 ros-humble-rmw-cyclonedds-cpp。 配置简单、在大数据量下表现稳定，不少机器人厂商偏好它
RTI Connextrmw_connextdds 商业产品，多用于对认证有要求的场合

切换方式（切换前必须先装对应的包）：

export RMW_IMPLEMENTATION=rmw_cyclonedds_cpp

通信双方的 RMW 实现必须一致。 不同 DDS 实现虽然都遵循 DDS 标准，但在实际互通上常有问题—— 一端用 Fast DDS、另一端用 Cyclone DDS，很可能互相看不见，而且不报任何错。 行业内不同厂商的默认选择并不统一（例如宇树的机器人常用 Cyclone DDS， 而不少平台沿用 Fast DDS），对接别家设备时，第一件事就是确认两边用的是不是同一个。

ROS_DOMAIN_ID：把自己和别人隔开

同一个局域网里如果有多人同时跑 ROS2，默认情况下大家的节点会互相发现， 话题混在一起。ROS_DOMAIN_ID 就是用来分隔的： 只有域号相同的节点才能看见彼此。

实际验证一下。在一个终端里用域 41 启动一个节点：

export ROS_DOMAIN_ID=41
ros2 run demo_nodes_py talker

另开终端，在同一个域里查看：

export ROS_DOMAIN_ID=41
ros2 node list
ros2 topic list
/talker

/chatter
/parameter_events
/rosout

再换一个域号查看，同一台机器上的同一个节点，就此消失：

export ROS_DOMAIN_ID=42
ros2 node list
ros2 topic list

/parameter_events
/rosout

节点列表是空的，话题里也没有 /chatter——只剩两个每个域都有的内置话题。

取值范围是 0 到 232。域号会被换算成 UDP 端口号， 超出范围会直接报错：

Calculated port number is too high. Probably the domainId is over 232 or portBase is too high.

默认值是 0。这意味着不做任何设置时，同网段所有人都在域 0 里挤着。 多人协作时约定各用各的域号，是最省事的隔离办法。

ROS_LOCALHOST_ONLY：彻底不上网

第三节见过这个变量。设成 1 时，节点只通过本地回环通信， 完全不对外广播：

export ROS_LOCALHOST_ONLY=1

两个变量的分工用一句话记：本机仿真用 ROS_LOCALHOST_ONLY=1， 接实机、跨机器用 ROS_DOMAIN_ID。前者适合只在本机开发、 或局域网噪声太大先把自己隔离出来排查；代价是跨机器通信随之失效—— 接了雷达实机、或机器人上的节点要连你桌面的 rviz2 时，它必须是 0， 这时靠域号把你和别人分开。

4.7 串口：另一种连设备的方式

不是所有设备都走网口。IMU、GPS、舵机控制板这类数据量小、要求实时的设备， 通常走串口。两者的区别值得记住：

网口（雷达）串口（IMU）
寻址方式IP 地址设备文件路径，如 /dev/ttyUSB0
要配什么IP、子网掩码波特率、数据位、校验位、停止位
能接几个一个网口接一整个网络一根线一个设备
典型速率100 / 1000 Mbps115200 bps 量级，慢三四个数量级

先找到设备文件。插上设备前后各跑一次，多出来的那个就是：

ls -l /dev/ttyUSB* /dev/ttyACM* /dev/ttyTHS* 2>/dev/null
crwxrwxrwx 1 root dialout 166, 0  7月 30 04:24 /dev/ttyACM0
crw-rw---- 1 root dialout 240, 1  6月  5 17:40 /dev/ttyTHS1
crw-rw---- 1 root dialout 240, 2  6月  5 17:40 /dev/ttyTHS2
名字来自哪
/dev/ttyUSB*USB 转串口芯片（CH340、CP2102、FTDI 等），最常见
/dev/ttyACM*自带 USB 接口的设备（很多 IMU、Arduino）
/dev/ttyTHS*板载硬件串口，Jetson 上是这个名字；PC 上通常是 /dev/ttyS*

权限。注意上面每一行结尾的组是 dialout，权限是 crw-rw----——只有 root 和 dialout 组的成员能读写。 普通用户直接打开会 Permission denied。 先确认自己在不在这个组：

groups
agx adm dialout cdrom sudo audio dip video plugdev render i2c lpadmin gdm sambashare weston-launch gpio jtop lrx

列表里有 dialout 就没问题。没有的话加进去：

sudo usermod -aG dialout $USER

加完组必须重新登录才生效（注销再登录，或重启）。 在当前终端里 groups 仍然看不到它——组信息在登录时就确定了， 和 source 只影响当前 shell 是同一类道理。 不要用 sudo 跑你的 ROS2 节点来绕过这个， 那会让整个节点以 root 身份运行，后患很多。

波特率与协议。串口两端必须事先约定好参数， 没有自动协商——这点和网口完全不同。

参数含义常见值
波特率每秒传多少位。两端必须完全一致 9600、115200、230400、921600
数据位一帧里有效数据几位8
校验位用于检错。N 无校验 / E 偶 / O 奇N
停止位一帧结束的标记1

这四项常缩写成 115200 8N1，意思是 "波特率 115200、8 数据位、无校验、1 停止位"。绝大多数 IMU 都是 8N1， 真正要确认的是波特率——查设备手册，或者试。

波特率设错的典型症状：能读到数据，但全是乱码。 因为采样时机对不上，位被切错了。读不到任何数据则通常是设备文件选错、 没权限、或线接反了（TX 要接对方的 RX）。

用 stty 查看和设置当前参数：

stty -F /dev/ttyUSB0            # 查看
stty -F /dev/ttyUSB0 115200     # 设成 115200

协议是厂商定的。波特率只解决"怎么把二进制位传过来"， 传过来的这堆字节怎么解释是另一回事。 典型的 IMU 数据帧长这样：

flowchart LR
    A["帧头<br/>0x55 0xAA<br/>标记一帧开始"] --> B["长度<br/>后面有几字节"]
    B --> C["数据区<br/>加速度 x y z<br/>角速度 x y z<br/>每个 2 或 4 字节"]
    C --> D["校验和<br/>前面所有字节相加<br/>用来验证没传错"]

每个字段占几字节、是有符号还是无符号、高位在前还是低位在前、 原始值要乘以什么系数才是真实物理量——这些只有设备手册知道。 好在常见 IMU 一般都有现成的 ROS2 驱动包，你不用自己解析； 但当数据看着不对时，你得知道该去手册里查什么。

5.9 回调：把函数交出去

这是理解 ROS2 的钥匙。你写好一个函数，交给别人，别人在合适的时机调用它； 你自己从不调用它。

    for i in range(n):
        func(i)


def on_tick(i):
    print("  on_tick 收到 i =", i)

  on_tick 收到 i = 0
  on_tick 收到 i = 1
  on_tick 收到 i = 2

现在把这两件事合起来，看清 rclpy.spin() 到底在做什么。 下面用纯 Python 模拟它——Day 1 的真实节点，结构与此完全一致：

class FakeNode:
    def __init__(self, name):
        self.name = name
        self.callbacks = []

    def create_timer(self, callback):
        # 只是把函数存起来，并不调用它
        self.callbacks.append(callback)


def fake_spin(node, rounds):
    """rclpy.spin() 干的就是这件事：
    不停地替你调用注册过的回调，直到你按 Ctrl+C。"""
    print(f"  [spin] 开始为节点 {node.name} 转圈")
    for _ in range(rounds):
        for cb in node.callbacks:
            cb()
    print("  [spin] 收到 Ctrl+C，退出")


node = FakeNode("talker")
count = {"n": 0}


def on_timer():
    count["n"] += 1
    print(f"  发布：{count['n']}")


node.create_timer(on_timer)     # 交出去，不加括号
fake_spin(node, 3)
  [spin] 开始为节点 talker 转圈
  发布：1
  发布：2
  发布：3
  [spin] 收到 Ctrl+C，退出

对照 Day 1 的真实代码，只是把 FakeNode 换成 rclpy 的 Node、 fake_spin 换成 rclpy.spin()：

self.timer = self.create_timer(0.2, self.on_timer)   # 交出回调
rclpy.spin(node)                                     # 交出控制权

rclpy.spin() 会一直阻塞到 Ctrl+C。 它之后的代码在那之前不会执行，所以"持续要做的事"必须写成回调， 不能写成 while True 循环。

finally 不管有没有出异常都会执行，所以清理代码放这儿最保险。 Day 1 每个节点的 main() 都是这个结构：

try:
    rclpy.spin(node)          # 一直阻塞
except KeyboardInterrupt:     # Ctrl+C 触发的就是这个异常
    pass                      # 安静退出，不打印红色堆栈
finally:
    node.destroy_node()       # 不管怎么退出，清理都要做
    rclpy.shutdown()

你看到的真正的原因怎么解决
ros2: command not found 当前终端没 source。不一定是没装 先 source /opt/ros/humble/setup.bash； 再不行用 ls /opt/ros/humble 确认到底装没装
colcon: command not found 只装了 ROS2，漏了 colcon——它是独立的包 sudo apt install python3-colcon-common-extensions
E: Unable to locate package ros-humble-desktop 软件源没加成功，或加完没 apt update cat /etc/apt/sources.list.d/ros2.list 核对内容， 然后 sudo apt update
NO_PUBKEY / signatures couldn't be verified GPG 密钥没装好，apt 拒绝来源不明的包 重做 2.3 步骤 ② 下载 ros.key
dpkg: dependency problems dpkg -i 装的包缺依赖，停在半成品状态 sudo apt install -f。不要重复 dpkg -i
Permission denied 在写没有权限的目录，或脚本没有执行权限 写系统目录用 sudo；跑脚本用 chmod +x 或 bash 脚本
新终端里 ros2 又用不了 source 只影响当前终端 把 source 写进 ~/.bashrc（3.5 节）
写进 .bashrc 了，当前终端还是不行 .bashrc 只在终端启动时读一次 关掉重开，或 source ~/.bashrc
ModuleNotFoundError: No module named 'rclpy' 用的 Python 不是系统那个（常见于 conda 抢占 python3） which python3 应为 /usr/bin/python3； 先 conda deactivate
IndentationError Python 缩进不一致，或混用空格和 Tab 统一 4 个空格。编辑器里开"显示空白字符"
UnboundLocalError 方法里漏写了 self. 见 5.7 节最后那个例子
ping 100% 丢包，一行错误都没有 目标和你不在同一子网，包被丢给默认网关后消失 ip -br addr 看自己的网段，按 4.5 节把主机加到目标所在子网
Destination Host Unreachable 路由是对的，同子网里喊了但没人应答 查对方：上电没、IP 对不对、网线插好没。ip neigh 会显示 FAILED
网卡有名字但没 IP，标着 NO-CARRIER 物理链路没通——网线没插好，或对端没上电 换线换口试；cat /sys/class/net/网卡名/operstate 应为 up
打开串口报 Permission denied 当前用户不在 dialout 组 sudo usermod -aG dialout $USER，然后注销重新登录。 不要改用 sudo 跑节点
串口能读到数据，但全是乱码 波特率设错了，采样时机对不上 查设备手册确认波特率，常见是 115200。 用 stty -F /dev/ttyUSB0 115200 改
两台机器网络通，ros2 node list 却看不到对方 ROS_DOMAIN_ID 不一致，或一端设了 ROS_LOCALHOST_ONLY=1，或两端 RMW 实现不同 按 4.6 节的排查树逐项对照。这三种都不报错，只是静默地看不见
Calculated port number is too high ROS_DOMAIN_ID 超过了 232 改成 0–232 范围内的值
局域网里冒出别人的节点和话题 大家都在默认的域 0 里 约定各用各的 ROS_DOMAIN_ID；只在本机开发时设 ROS_LOCALHOST_ONLY=1

课后回顾

几道典型选择题，先作答再展开答案；答错的回到括号里的小节重读。 考核题面由带教老师另行下发。

  1. 敲 ros2 报 ros2: command not found，这说明什么？

    1. ROS2 没有安装
    2. bash 按 PATH 找不到名叫 ros2 的程序，和装没装是两回事
    3. ROS2 版本不对
    4. 必须用 root 身份运行
    答案与解析

    B。查 ls /opt/ros/humble：目录在，就是装了没 source（3.3）；目录不在，才是真没装（1.1、3.2）。

  2. 想把一行配置追加到 ~/.bashrc 末尾，该用哪个？

    1. echo "…" > ~/.bashrc
    2. echo "…" >> ~/.bashrc
    3. 两个都行
    4. cat "…" >> ~/.bashrc
    答案与解析

    B。> 是覆盖写入，会把整个文件清空只剩你这一行（1.4）。cat 打的是文件内容，不能这样传字符串（1.4）。

  3. source setup.bash 和 bash setup.bash 的区别是？

    1. 没有区别
    2. source 在当前 shell 里就地执行，设的变量留下来；bash 另开子进程执行，变量随子进程退出而消失
    3. source 更快
    4. bash 需要可执行权限，所以更安全
    答案与解析

    B。这就是每开一个新终端都要重新 source 的原因（3.3）。

  4. 主机 192.168.160.200/24，雷达 192.168.123.10。ping 雷达会看到什么？

    1. 能通
    2. Destination Host Unreachable
    3. 一行错误都没有，最后 100% packet loss
    4. 提示子网掩码错误
    答案与解析

    C。掩码 /24 前三段必须相同才同子网；不同子网的包被丢给网关后石沉大海，静默丢包正是「子网配错」的典型指纹（4.1、4.4）。

  5. 只在本机跑仿真、不想被同网段的人干扰，最干净的做法是？

    1. export ROS_DOMAIN_ID=99
    2. export ROS_LOCALHOST_ONLY=1
    3. 拔网线
    4. 把 WiFi 改成静态 IP
    答案与解析

    B。本机仿真用 ROS_LOCALHOST_ONLY=1，彻底不对外广播；要接雷达实机或多机通信时它必须为 0，改用 ROS_DOMAIN_ID 隔离（3.4、4.6）。

  6. 串口 IMU 能读到数据但全是乱码，最可能的原因是？

    1. 线接反了
    2. 没加入 dialout 组
    3. 波特率两端不一致
    4. 设备文件选错了
    答案与解析

    C。波特率错 = 采样时机错位，位被切错，表现为「有数据但乱码」；读不到任何数据才去查线序、权限、设备文件（4.7）。

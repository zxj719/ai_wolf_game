一、包的完整解剖

Day 1 说过 package.xml 是身份证、setup.py 是打包说明。 今天要往包里加 launch 文件和参数文件，这两份说明书必须逐项看懂。

1.1 package.xml：给 ROS2 和 rosdep 看的

<package format="3">
  <name>day2_demo</name>
  <version>0.0.0</version>
  <description>Day 2 示例</description>
  <maintainer email="intern@example.com">intern</maintainer>
  <license>Apache-2.0</license>

  <depend>rclpy</depend>
  <depend>std_msgs</depend>

  <exec_depend>ros2launch</exec_depend>

  <export>
    <build_type>ament_python</build_type>
  </export>
</package>

依赖标签有三种，区别在于什么时候需要它：

标签含义例子
<build_depend> 只在编译时需要 C++ 包的头文件依赖。纯 Python 包几乎用不到
<exec_depend> 只在运行时需要 ros2launch：编译用不上它，跑 ros2 launch 时才要
<depend> 编译、运行都需要，等于上面两个一起写 rclpy、std_msgs。拿不准就用它

这些声明有两个真实作用：colcon 靠它决定包的编译顺序； rosdep 靠它自动安装缺的系统依赖。写漏了不一定立刻报错， 但换一台机器部署时就会缺东西。

补充：ament_cmake 包长什么样（阅读材料，不要求会写）

C++ 包的构建类型是 ament_cmake，说明书是 CMakeLists.txt， 角色相当于 setup.py。你会在两个场合遇到它： 读别人的 C++ 包（比如 Livox 驱动），以及自定义消息接口—— 接口包必须是 ament_cmake 类型，即使项目其余部分全是 Python。 本课程用不到自定义接口，认得出来即可。

1.2 setup.py：逐项讲清

这是今天的主战场。day2_demo 的完整版：

import os
from glob import glob

from setuptools import setup

package_name = 'day2_demo'

setup(
    name=package_name,
    version='0.0.0',
    packages=[package_name],
    data_files=[
        ('share/ament_index/resource_index/packages', ['resource/' + package_name]),
        ('share/' + package_name, ['package.xml']),
        # 下面两行是本日核心：把 launch/ 与 config/ 装进 share 目录。
        # 不写它们，colcon build 不报错，但 ros2 launch 找不到 launch 文件。
        (os.path.join('share', package_name, 'launch'), glob('launch/*.launch.py')),
        (os.path.join('share', package_name, 'config'), glob('config/*.yaml')),
    ],
    install_requires=['setuptools'],
    zip_safe=True,
    maintainer='intern',
    maintainer_email='intern@example.com',
    description='Day 2 示例：library 复用、launch、namespace 与参数文件',
    license='Apache-2.0',
    entry_points={
        'console_scripts': [
            'talker = day2_demo.talker:main',
            'listener = day2_demo.listener:main',
        ],
    },
)
项作用写错的症状
packages 哪些目录是要安装的 Python 包 漏了 → ModuleNotFoundError
data_files 代码之外还要安装什么、装到哪。 launch、YAML、地图、URDF 全靠它 编译不报错，ros2 launch 时才炸（见第四节实测）
entry_points 把"函数"变成"可执行名"：talker = day2_demo.talker:main 读作"可执行 talker = 模块 day2_demo/talker.py 里的 main 函数" No executable found

data_files 每一项是一个二元组 (装到哪, [装什么])。 glob('launch/*.launch.py') 把 launch/ 下所有 launch 文件列出来， 以后加新文件不用改 setup.py。

为什么装进 share/？约定：lib/ 放可执行， share/ 放随包分发的数据文件。ros2 launch 只会去 share/<包名>/ 底下找。

阶段成果：能对着 setup.py 的每一行说出 "删了它会出什么错"。

二、把逻辑抽成 library

Day 1 的 listener 把"乘 2"写在回调里。逻辑一复杂（滤波、坐标变换、协议解析）， 这么写的代码既没法给第二个节点复用，也没法单独测试。 解法：与 ROS2 无关的逻辑放进普通 Python 模块。

day2_demo/
├── __init__.py
├── math_lib.py      ← 纯逻辑，不 import rclpy
├── talker.py        ← 节点，薄薄一层
└── listener.py      ← 节点，薄薄一层

math_lib.py：

def scale(value: int, factor: int) -> int:
    """把 value 放大 factor 倍。"""
    return value * factor


def period_of(hz: float) -> float:
    """频率(Hz) 换算成定时器周期(秒)。"""
    if hz <= 0:
        raise ValueError(f"频率必须为正数，收到 {hz}")
    return 1.0 / hz

节点里导入。注意路径是包名.模块名，跟文件在同一目录也要这么写—— 运行时代码在 install/ 里，相对导入会断：

from day2_demo.math_lib import scale, period_of

好处立刻兑现：不启动任何 ROS2 的东西就能验证逻辑（在 workspace 根目录， build 并 source 之后）：

python3 -c "from day2_demo.math_lib import scale; print(scale(21, 2))"
42

阶段成果：math_lib.py 进包，两个节点都从它导入， 命令行一句话可验证。

三、参数：把"会变的数"搬出代码

发布频率、倍数、串口波特率、雷达 IP——这些值今天是 A 明天是 B。 写死在代码里，每改一次都要重新编译。ROS2 的答案是参数（parameter）： 节点声明"我有哪些可调项"，值从外部喂进来。

3.1 节点侧：先声明，再读取

class Talker(Node):
    def __init__(self):
        super().__init__('talker')
        # declare_parameter(名字, 默认值)：没有这行，外部传进来的参数会被拒收
        self.declare_parameter('publish_hz', 2.0)
        hz = self.get_parameter('publish_hz').value

        self.pub = self.create_publisher(Int32, 'counter', 10)
        self.count = 0
        self.timer = self.create_timer(period_of(hz), self.on_timer)
        self.get_logger().info(f'talker 已启动，publish_hz={hz}')

三个要点：

  • 默认值同时定了类型。2.0 声明的是浮点参数， 外部喂整数 5 会被拒。频率这类值一律写成 5.0
  • 默认值别写你想要的值。YAML 没生效时节点会拿默认值继续跑、 不报任何错；默认值和目标值一样，你就发现不了。示例里故意用 2.0， 考核要求 5 Hz——频率不对立刻暴露
  • 忘了 declare_parameter 就去 get_parameter，节点启动即崩：
rclpy.exceptions.ParameterNotDeclaredException: ('Invalid access to undeclared parameter(s)', 'multiplier')

3.2 文件侧：config/params.yaml

/day2/talker:
  ros__parameters:
    publish_hz: 5.0
/day2/listener:
  ros__parameters:
    multiplier: 2

结构固定三层：节点全名 → ros__parameters（两个下划线）→ 参数表。

顶层键必须是节点的完整名字，包括 namespace。 节点在 /day2 下，键就必须是 /day2/talker。 写成 talker: 或 /talker: 不报任何错， 参数被静默忽略，节点拿默认值继续跑。这是今天最隐蔽的坑，实测现象见 4.5。

阶段成果：频率、倍数都进了 YAML，改它们不再碰代码。

四、launch：一条命令拉起整个系统

4.1 launch 文件的三要素

launch 文件是一段 Python：定义一个 generate_launch_description() 函数， 返回要启动的节点列表。

import os

from ament_index_python.packages import get_package_share_directory
from launch import LaunchDescription
from launch_ros.actions import Node


def generate_launch_description():
    params = os.path.join(
        get_package_share_directory('day2_demo'), 'config', 'params.yaml')

    return LaunchDescription([
        Node(package='day2_demo', executable='talker', name='talker',
             namespace='day2', parameters=[params], output='screen'),
        Node(package='day2_demo', executable='listener', name='listener',
             namespace='day2', parameters=[params], output='screen'),
    ])
要素干什么
generate_launch_description() 固定入口，ros2 launch 找的就是这个函数名
Node(...) 描述一个要启动的节点：哪个包、哪个可执行、叫什么、 在哪个 namespace、喂什么参数。output='screen' 让节点日志打到当前终端
get_package_share_directory() 按包名找到它安装后的 share 目录—— 参数文件的路径不能写死，每台机器不一样

ros2 launch day2_demo day2.launch.py 的完整查找链：

flowchart TD
    A["ros2 launch day2_demo day2.launch.py"] --> B["按包名找 share 目录<br/>install/day2_demo/share/day2_demo"]
    B --> C{"里面有 day2.launch.py 吗"}
    C -- "没有（data_files 没写）" --> X["was not found in the share directory<br/>见 4.4"]
    C -- 有 --> D["执行 generate_launch_description()"]
    D --> E["逐个拉起 Node<br/>套 namespace，喂参数文件"]
    E --> F["节点各自 declare_parameter<br/>从 YAML 里认领自己的段落"]

4.2 namespace 与相对话题名

launch 里给了 namespace='day2'。它对节点名和话题名的影响不一样：

代码里写的实际结果为什么
节点名 talker/day2/talker 节点名总是被 namespace 加前缀
话题 counter（相对名）/day2/counter 相对名跟着 namespace 走
话题 /day1/counter（绝对名）/day1/counter 绝对名无视 namespace，写哪是哪

所以今天必须把 Day 1 代码里的 /day1/counter 改成相对的 counter。不改的话 launch 照样能跑， 但话题跑在 /day1/... 下面，namespace 形同虚设——评分脚本按 /day2/counter 找，一分拿不到。namespace 的价值 Day 3 会真正兑现： 两台机器人各占一个 namespace，同一套代码互不打架。

4.4 实测：把 data_files 两行删掉会怎样

把 setup.py 里 launch/config 那两行注释掉， 删干净 build/install 再重编（原因见下面的警告）：

rm -rf build/day2_demo install/day2_demo
colcon build --packages-select day2_demo
source install/setup.bash
ros2 launch day2_demo day2.launch.py
file 'day2.launch.py' was not found in the share directory of package 'day2_demo' which is at '/home/agx/ws_demo/install/day2_demo/share/day2_demo'

注意时间差：colcon build 全程无报错， 问题在 ros2 launch 时才暴露。报错信息其实把答案说全了—— 它去 share 目录找过了，没有。谁负责把文件放进 share？data_files。

为什么必须先删 build/install： 如果这个包以前成功装过 launch 文件，旧副本会一直留在 install/ 里——删掉 data_files 再普通重编， ros2 launch 依然能跑（用的是旧文件），你完全看不出 setup.py 已经坏了。实测确认过这个现象。遇到任何"改了配置没反应"， 第一招都是删干净重编。

4.5 实测：YAML 键写错会怎样

把 params.yaml 顶层键从 /day2/talker 改成 /talker，重编重启，没有任何报错。然后：

ros2 param get /day2/talker publish_hz
ros2 topic hz /day2/counter
Double value is: 2.0
average rate: 2.000

节点拿着代码里的默认值 2.0 在跑——YAML 那段被静默跳过了。 这就是 3.1 说"默认值别写目标值"的原因：默认值要是也写 5.0， 这个错误今天不炸，留到某天你改参数发现怎么改都没反应。

阶段成果：一条命令启动全系统；两类"不报错的错" （data_files 残留、YAML 键失配）都亲手复现过，知道怎么查。

课后回顾

几道典型选择题，先作答再展开答案；答错的回到括号里的小节重读。 考核题面由带教老师另行下发。

  1. setup.py 里 data_files 没写 launch 那一行，现象是？

    1. colcon build 报错
    2. ros2 launch 报 file '…launch.py' was not found in the share directory，而 build 全程无报错
    3. launch 能跑但节点起不来
    4. ros2 pkg list 里看不到这个包
    答案与解析

    B。build 只按说明书办事，说明书漏了它不检查；错误在 ros2 launch 去 share 目录找文件时才暴露（4.4 实测）。

  2. launch 里 namespace='day2'，代码里写 create_publisher(Int32, '/day1/counter', 10)。实际话题是？

    1. /day2/day1/counter
    2. /day2/counter
    3. /day1/counter
    4. 启动报错
    答案与解析

    C。以 / 开头的绝对名无视 namespace，写哪是哪；只有相对名 counter 才会被加上 /day2 前缀（4.2）。

  3. params.yaml 顶层键写成了 listener:（节点实际在 /day2 下）。会发生什么？

    1. ros2 launch 报错
    2. 节点启动时报参数文件无效
    3. 什么错都不报，节点拿 declare_parameter 的默认值继续跑
    4. 参数变成字符串类型
    答案与解析

    C。键必须一字不差等于节点全名 /day2/listener，不匹配的段落被静默跳过（4.5 实测）。这也是「默认值别写目标值」的原因。

  4. 节点里没写 declare_parameter('multiplier', …) 就调用 get_parameter('multiplier')，结果是？

    1. 返回 None
    2. 返回 YAML 里的值
    3. 抛 ParameterNotDeclaredException，节点启动即崩
    4. 自动声明一个空参数
    答案与解析

    C。先声明后读取是硬规则；声明的默认值同时定了参数类型（3.1）。

  5. ros2launch 在 package.xml 里应该用哪个标签声明？

    1. <build_depend>
    2. <exec_depend>
    3. <test_depend>
    4. 不用声明
    答案与解析

    B。编译用不上它，跑 ros2 launch 时才需要——只在运行期需要的依赖用 exec_depend；编译运行都要的（rclpy、std_msgs）用 depend（1.1）。
